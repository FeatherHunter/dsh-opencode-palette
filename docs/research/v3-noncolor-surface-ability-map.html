第一性口径（与 P1/P2/P3 一致）：
  1. 排印 182 的结构：2 个全局字族 + 30 个复合（一次给字号/行高/字重/字族，宿主用 font: var(...) 简写消费）+ 150 条长手（5 轴 × 30 角色）。宿主消费的是复合，长手大多无人消费 → 长手死名不假装可用，但全部登记（用户要全量）。
  2. 可改能力落点：排印能力优先落在复合（token 写入即生效）；只改某角色字号/行高时，复合不可拆 → 走规则层（如 p / h1 / code 选择器），这与 P2「有上游走上游、无上游落规则」同一判据。
  3. --dsh / 局部变量不是用户能力：它们是宿主内部布局量/组件私有实现，元素级声明或 JS 写入，body 级覆盖无效；登记目的是「以后不用再翻源码」，tier=advanced/内部，不建用户能力条目。
  4. 不可达诚实标注：--dsw-mask-blur 宿主钉死 none；--dsh-scrollbar-thumb* 由 JS/组件逐元素写 → 只能运行时重写；--dsw-corner-shape 目前无消费方。

三、P4 对 palette 的影响

  • 新增能力域：typography（排印）、radius（圆角）、runtime（运行时布局量登记）、mask（蒙层）、structure.corner.shape（圆角形状）。
  • 排印复合 = stable 能力（30 条）；长手 150 条 = dead/advanced（登记但不作为默认入口）；显示改字号/行高用规则层能力（P5 定稿时进 palette 条目）。
  • 运行时 148 = 「已知但不可从主题层写」，写入 palette/tokens.yaml 的 runtime 段与 _index 计数，编辑器不暴露为可点条目。
  • 本表完成后，公开 425 全部有归宿：P1 颜色 222 + P4 非颜色 203；运行时 573 = 425 + 148 全部登记，「全量」在集合意义上闭合。
