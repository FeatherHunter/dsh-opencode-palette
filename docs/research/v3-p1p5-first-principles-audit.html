  • C5 需求可溯源：P1–P4 每一行都能映射到具体能力或直绑定；24 条 idea 有归属票。

3.1 三个选项

选项做法代价
A（推荐）单一 owner① 重复语义行合并：保留手写/规范 id，其余进 `merged_from` 后删除；② 区域级旋钮改写规则层（如 `border-radius: <值>` 写到区域锚点，保留旋钮但不抢 token）；③ 宿主耦合项（标题栏底色=侧栏色派生、标题栏字色=主文字色）登记为 derived，不设独立旋钮，文档写明。窗口区会少一个「标题栏独立配色」旋钮（宿主物理限制，写文档说明）；区域圆角/链接色改为规则实现（实现技术变一条，但能力仍在）。
B 显式多写者每个 token 保留多条能力，但要求显式 `shared_with` 声明 + 写入顺序（后写覆盖），编辑器对共享 token 的旋钮加警示。用户可能同时看到两个互相覆盖的旋钮，结果依赖顺序；违背「一个 token 一个语义」。
C 全部合并为一每个 token 只留一条能力，删除区域级旋钮与标题栏旋钮。菜单最短，但损失区域级表达力（用户无法单独调代码块圆角/链接色）。
