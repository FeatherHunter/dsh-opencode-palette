P3 DOM 操作层（C3）→ 能撑哪些能力、上限在哪（宿主 rc.3 @ 1f81c04）

前两份：P1 颜色 222（v3-color-222-ability-map.html）、P2 私有变量 + 锚点（v3-private-surface-ability-map.html / v3-anchor-surface-map.html）。本份 = 第三种实现技术：DOM 操作。

一页结论：
  1. DOM 层能撑的「炫酷效果」最多：背景媒体、毛玻璃、渐变蒙层、噪点纹理、图标替换、入口按钮、滚动条/选区/焦点环样式、hover 动效、标题栏配色，全部可行。
  2. 但它是唯一会碰「结构」的层，按你 U7 的裁定分三级：装饰性 DOM（插图层/换图标）= 正式；结构性改动（隐藏/移动/重排/增删节点）= 实验、默认关闭。
  3. 存活率是硬约束：结构性改动在「宿主重渲染」时只剩 1/4 能活；装饰性 = 插图层/图标替换用 MutationObserver 幂等重放 才能稳定。
  4. 窗口外壳里，标题栏底色/字色可以做（token 探针 + setTitleBarOverlay）；标题栏高度/按钮形状位置/macOS 菜单不能做（原生）。

二、DOM 层的硬边界（做不到 / 不建议）

  • 原生窗口外壳内部：标题栏高度、按钮形状/位置、macOS 原生菜单 —— 原生绘制，DOM/CSS 都改不了。
  • 跨 Shadow Root：主 UI 无 shadow，但桌面壳里有 2 处 closed/open shadow；到不了里面。
  • 宿主内部状态：会话数据、滚动位置、选中态 —— 读不到可靠语义，别做「按状态换色」。
  • 离开文档的层：iframe 里的文档预览内容不受我们的样式影响（跨文档）。
  • React 重渲染：结构性改动不幂等重放会被还原；装饰性 DOM 必须 observer 重放。

三、四道验收在 DOM 能力上的含义（U20 的实现口径）

验收DOM 能力怎么过
宿主重渲染存活插图层应挂在 body/稳定父节点、不进 React 树 → 天然存活；图标替换/入口按钮靠 MutationObserver 幂等重放；结构性改动标记「可能丢失」，编辑器里提示
主题切换存活切换 = 卸载旧 plan + 应用新 plan；所有 dom write 必须带稳定 id + teardown，切换差集清理
卸载全还原每个 dom write 必须可逆：删自己插的节点、恢复被改的属性（记录原值）、断开 observer
上游升级不炸锚点走 probe：selector_exists = unknown → 降级下一候选；都不中 → 跳过 + 诊断，不抛错

四、rc.3 对 DOM 能力的三条影响（已确认）

  1. 3 个新官方 slot：可放「打开主题设置」入口（能力 #11），不用再靠哈希类猜位置。
  2. .panelRow 冲突：它现在同时是「更多」按钮的类（button.panelRow[aria-haspopup="menu"]、button.viewsMore）→ 我们的规则要 :not([aria-haspopup]) 排除，否则会把菜单按钮一起改坏。
  3. 几何松动：会话标签行 gap: 16px 20px + flex-wrap: wrap、侧栏行距 2px、Tooltip 多 data-side="left" 与 overflow:auto → 依赖固定尺寸/溢出的装饰效果要按 rc.3 重新验收（旧截图不算数）。

四·五、明确不做清单（诚实边界，避免「看起来能」）

  • 音频 / BGM：不在外观语义内；主题包若真要放音频属于扩展层（B/C），本票不做能力条目。
  • Canvas / WebGL / shader：宿主主 UI 无 canvas（唯一 canvas 在 PDF 预览，属文档内容，不是外观）；做不了「shader 材质」这类效果，最多 CSS 近似。
  • 原生窗口外壳内部：标题栏高度、按钮形状/位置、macOS 原生菜单 —— 原生绘制，DOM/CSS/token 都不可能。
  • 跨文档 / 跨 Shadow Root 内容：iframe 文档预览、桌面壳 closed shadow 内部不受我们控制。
  • 非外观的功能项（点赞/统计/市场/分发/issue 模板等）：属 #132 / #154 / 地图其他票，不在 P1–P3 范围。
