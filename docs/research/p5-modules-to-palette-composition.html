palette.yaml 由全部底层 YAML 合成（机制与分工）

一、两个角度，不混用

角度对象谁维护内容
主题设计者（用户 / 主题作者 / 外部 AI） 主题包：<主题目录>/theme.yaml + assets/ 主题作者 只写能力 id + 值 + 资源文件；看不到任何宿主 token 名
插件开发者（我们） palette/ 目录（能力集） 本仓库 词表、值类型、写原语、资源策略、探测、锚点、宿主 token 事实、能力菜单

所以不存在「主题设计者手写 palette.yaml」这回事。palette/ 整体是开发者侧的东西。

二、palette.yaml 不是手写的，它由底层 YAML 合成

palette/capabilities.yaml   手写能力源（28 条手写能力 + 控件模板）
palette/vocabulary.yaml     词表：区域/角色/属性/recipe/状态/语言/能力域 34
palette/values.yaml         值类型 23 种 + Unicode 范围 + 变量语法
palette/primitives.yaml     写原语：token/rule/dom/host_api + realization 契约
palette/assets.yaml         资源类型与安全策略
palette/probes.yaml         探测原语
palette/anchors.yaml        DOM 锚点 + 控件清单
palette/tokens.yaml         宿主 token 事实表 425 条 + runtime 148 条登记
docs/research/*.json        P1–P4 逐条讨论表（能力菜单的来源）
                    ↓  scripts/research/gen_palette_v5.py（可重跑）
palette/palette.yaml        合成视图（32 段）：grammar / vocabulary / value_types /
                            write_kinds / realization / policies / assets / probes /
                            anchors / controls / control_templates /
                            capabilities 331 / direct_bindings 425 /
                            token_summary / runtime_summary / generated 溯源

三、palette.yaml 里有什么

段内容来自
grammar / capability_domains / regions / roles / properties / recipes / states / languages / catalogid 文法与词表全量vocabulary.yaml
value_types / scripts / variables_spec / semantics值类型定义、Unicode 范围、变量语法values.yaml
write_kinds / realization / policies写原语与策略、realization 契约primitives.yaml
assets_policy / assets_kinds资源安全策略与类型assets.yaml
probes探测原语与环境probes.yaml
anchors / controls宿主锚点候选与控件清单anchors.yaml
token_summary425 token 的命名空间、颜色轴、状态模型摘要tokens.yaml
capabilities 331能力菜单（语义能力 + token 能力 + DOM 效果）capabilities.yaml + P1–P4 表
direct_bindings 425425 个公开 token 的直绑定兜底（id = token.<ns>.<名字>）tokens.yaml
runtime_summary运行时 148 条局部分组摘要（不建用户能力）tokens.yaml runtime 段
generated溯源：由哪些模块合成、生成器、宿主版本生成器写入

四、为什么这样

  • 单一事实源：每个事实只在它的模块里写一次；palette.yaml 是只读合成视图，门禁逐段比对，不一致即报错。
  • 主题设计者只写 theme.yaml：能力 id 拼错即报错；宿主名全部藏在 palette。
  • 可扩展：宿主升级 → 重扫 tokens.yaml → 重跑生成器；新增能力 → 改 capabilities.yaml → 重跑。palette.yaml 永远由机器重算，不靠人抄。
  • 可审计：P1–P4 每一行 → 能力/直绑定的落点可逐行核对（v3-p1p4-to-yaml-crosswalk.html）。

五、与上一版说明的差异（已纠正）

上一版把 palette.src.yaml 当成唯一手写源、把 palette.yaml 当成「生成物」。正确模型是：

  • 手写源不是单独一个「src」文件，而是全部底层模块，其中能力菜单的手写部分在 capabilities.yaml（与 vocabulary/values/… 平级的一个模块）。
  • palette.yaml 是所有底层模块的合成视图（32 段），不再只含 capabilities + direct_bindings。
  • 门禁新增逐段一致性校验：palette.yaml.X 必须等于对应模块的 X。
