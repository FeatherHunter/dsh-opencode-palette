P1 / P4 的内容落到哪些 YAML？

回答：「P4 也是在 P1 的 yaml 中增加内容吗？」· 2026-10-24

不是「加到 P1 的 yaml」——P1 和 P4 是同一批 palette/ YAML 的两种内容来源：
① 登记层 tokens.yaml：425 条 token 全在这一份里（颜色 222 + 非颜色 203，按大族/子组分节）。 ② 能力层 palette.yaml：只收「能变成用户能力」的条目（颜色语义 + 排印/圆角等），运行时 148 条不进能力层。

1. 现在的事实：P1/P4 的逐条表还是研究产物，还没写进 YAML

P1（颜色 222）与 P4（非颜色 203 + 运行时 148）目前是 HTML + JSON 清单，用来逐条讨论、确认分类。它们还不是 palette/ 的 YAML 内容。

把清单变成 YAML 是 P5 定稿要做的事——不是现在这一步，也不是「往 P1 的 yaml 里塞」。

2. P5 定稿时，P1/P4 的行分别落哪里

内容落到哪个 YAML为什么
P1：颜色 token 222 条（含姓名/状态/消费/声明/值类型/探针） palette/tokens.yaml（登记） 登记层是「宿主有什么」的唯一真源；颜色与非颜色同表，按 family → subgroup → status 排
P4：非颜色 token 203 条 palette/tokens.yaml（同一份，非颜色节） 同属「宿主 token」；不另建第二张表，避免两份口径
P4：运行时局部变量 148 条 计划：palette/tokens.yaml 新增 runtime 段（登记）；能力层不收录；当前仅存于 P4 的 JSON/HTML 它们不是公开契约、body 级覆盖无效；登记只为「不再翻源码 / 证明没漏」
P1：颜色语义能力（如 global.page.background） palette/palette.yaml（能力菜单） 能力层 = 用户能在 theme.yaml 里写什么，绑定链指向登记层条目
P4：排印复合 30 / radius 6 / menu 材质等能力 palette/palette.yaml（能力菜单） 同上；排印长手 150 默认只登记、不生成能力（dead）
能力域 / 文法（P4 新增 typography、radius、runtime、mask） palette/vocabulary.yaml 已在：capability_domains 现在 33 个
值类型（长度 / 字体栈 / 字体资源 / 颜色 …） palette/values.yaml 决定每个能力能写什么值、怎么校验
P3 锚点（data-slot / data-attribute / role） palette/anchors.yaml 规则层能命中谁
探针（token_live 等） palette/probes.yaml 加载时判断「宿主还认不认这条」
写入原语（token / rule / dom） palette/primitives.yaml 能力到底怎么写进去
资源约束（图片/字体/视频） palette/assets.yaml 主题包里允许放什么

一句话区分：tokens.yaml 回答「宿主有什么可以改」（425 全量，含改不动的）；palette.yaml 回答「用户能改什么」（能力菜单，只收可达的）。P1 与 P4 同时喂这两层：登记层全量收，能力层只收能用的。
