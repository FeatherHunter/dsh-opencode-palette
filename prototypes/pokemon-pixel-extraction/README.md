## 2. 设计理念（决策，不是配色表）

1. **单一主角** — 黄色是唯一的品牌色。`primary` = `#FEC901`（30 周年的黄场）；`borderActive` = `#F1D379`（图鉴立绘耳尖的亮黄，1316 个真实像素）。同族不同源、亮度差一档：ΔL\* +3.8、ΔE76 36.9。
2. **反相按钮** — 黄底 + 引擎自动选的 `#141414` 深字，和宝可梦 logo 的画法一致，11.90:1。
3. **亮度分层** — 代码 `#000000` → 页面 `#0C0C10` → 左栏 `#121212` → 面板 `#191917` → 浮层 `#1C1C22`；发丝线只留 `#40404A` 一档。
4. **语义有出处** — 杰尼龟甲 = info，妙蛙种子的叶绿 = success，小火龙 = warning，妙蛙种子的身红 = error。
5. **角色不打架** — 25 个设计角色两两不同；注释与运算符都退到核心语法之下。

> **一条硬约束：浮层底的亮度上限。** 错误红 `#F93D32` 压在浮层 `#1C1C22` 上仍要过 4.5:1，浮层的相对亮度就不能高过 **.014** —— 于是中性层被压得很扁，只有五级，层级靠发丝线（`#40404A`）而不是亮度拉开。这是「亮色不好找」的真实原因，不是偷懒。

## 4. 对抗式审查（红队）—— 全部结论

方法：每条批评先量化，再与仓库 23 套 IP 预置横向对标；**只有比全库常态更差**的才算缺陷。不这么做就会把仓库的共性当成自己的错。

### 4.1 真缺陷，已修（1 条）

**primary 与 borderActive 原本是同一个颜色**：ΔE76 **0.83**、ΔL\* **1.1**、色相差 **0.1°**。原稿写的「同族两级」「边界比主色亮一档」都是假的。全库 23 套这一对的 ΔE 中位 **47.4**，原方案是倒数第二（只有 hello-kitty 的 0.0 更差）。

不是纸面问题：合成器里黄色描边（聚焦框）与黄色方块（发送按钮）**隔 10 像素**却用同一块颜色画。

**修法**：`borderActive` → `#F1D379`（图1 耳尖亮黄，1316 真实像素），ΔE 36.9 / ΔL\* +3.8，落回全库常态区间。见 `04-composer-focus.png`。

### 4.2 文案里被证伪并已改（3 条）

| 原文 | 核算 | 改后 |
|---|---|---|
| 「错误红是参考图里最亮的正红」 | 图内有更亮的红（`#FF6B3D` L=.3211 等），但**各只有 1 个像素**（JPEG 振铃） | 「**像素量可用**的最亮正红（1984 px）」 |
| 「饱和度预算几乎全给了黄色」 | S≥0.55 的 12 个颜色：黄/金 **4**、红 **4**、蓝/青 3、橙 1 —— 红族与黄族并列 | 「黄与红两族并列，各 4 个颜色」 |
| 「同族两级，边界比主色亮一档」 | 见 4.1 | 随改色一并改写 |

### 4.3 提了但被全库对标否掉，撤回（4 条）

| 我的批评 | 全库实际 | 处置 |
|---|---|---|
| 气泡底只有 1.11:1，几乎与页面同色 | 23 套中位 **1.13**、最低 1.01；GitHub 的 1.55 是特例不是标准 | **撤回** |
| 正文 16.89:1 过高，halation 风险 | 中位 **15.39**、最高 17.83 —— 族内高端但非异常，是全仓库暗色 IP 的共性 | **降级为注记** |
| primary↔warning 色相差 15.7° 太近 | 中位 **38.8°**、最低 14.9°（harry-potter）；我是第二紧，但已有 3 套同处 15–19° 带内 | **降级为留意项** |
| 「仓库 house style 就是 primary==borderActive」 | 23 套里只有 **2 套**如此 —— 说反了，保持不同才是多数派 | **更正** |

### 4.4 查了但判定不修（1 条）

**语法 `function` 与 `type` 色相只差 4.3°**（`#95C7F8` H209.7 / `#6E9BBC` H205.4，ΔE 18.2），是核心五色里最接近的一对。修它要把 type 挪到第三个色相 —— 可用的精确像素只剩低明度青 `#658F8B`（5.85:1，仅 72 px），那会迫使注释与运算符退到几乎不可分辨的两档灰（`#7A7A7F` 4.92 / `#7D7D82` 5.13，ΔE≈1.5）。**代价大于收益，记档保留。**

### 4.5 留下不修的已知限制（3 条）

1. **浅色层级只有三级。** 精确像素集里够亮的只有 `#FFFFFF`(L 1.0) / `#EEEEF4`(.859) / `#FDE7B5`(.814)。于是标题（16.06:1）在**对比度上低于**正文（16.89:1）—— 层级是倒挂的，靠**色相差 30.1**（暖奶油 vs 冷白）加字号字重顶住。`text ↔ markdownStrong` 的 ΔE 只有 6.5（只差亮度），是全主题最弱的一对；但把纯白给 strong、奶油给标题，倒挂会挪到标题身上（更糟）—— 现状是三个选项里较好的一个。
2. **primary 在真实客户端被超载。** `map-dsh.ts` 把它刷成 5 种：`button-primary-fill` 纯填充、`brand-text` 品牌文字、`button-primary-dimmed` 20% 悬停（叠出 `#3C310D`）、`sidebar-nav-item-active-accent` 35% 侧栏强调（叠出 `#64520C`）、`state-business-primary` 业务状态。黄色既当品牌又当「进行中」。本设计稿只呈现了其中一种画法。
3. **IP 性格的成立度有限。** 37 个颜色里约 **22 个**落在「任何暗色主题都会用」的常规区间（中性阶 + 语义四色 + 语法分层），真正由宝可梦决定的约 15 个。**「所有颜色来自图片」= 可溯源性，成立；「主题体现了 IP 的性格」= 只部分成立。** 换一套同题材参考图，这套主题的骨架几乎不变，只有 hex 会变。这是「取自图片」的诚实边界，不是缺陷。

### 4.6 结论

**判尺是及格线，不是优秀线。** 仓库判尺测得出对比度、角色碰撞、语法退后、ΔE、色相孤岛；它测不出层级倒挂、同屏近色与气质归属 —— 4.1 / 4.4 / 4.5 节全部落在判尺覆盖不到的地方。所以「0 违例 0 告警」**不能**被当成质量结论。
