## 0. 审查的三条规矩

1. **不预设立场，先证伪。** 每个颜色先假设它是对的，然后去找那个能把它推翻的观察；「看起来不错」不构成证据。
2. **判尺是地板不是目标。** 4.5 / 3.0 过了只是及格；要看的是余量，以及**过线之后引擎会不会把我的色改掉**。
3. **不看自己的稿，看像素和源码。** 取 `src/engine/resolve.ts` 的真实语义、取原图里该色的最近邻裁切，去反驳自己写的叙事。

用户给这条线的硬约束只有一条，但它是这套稿的宪法：

> **所有颜色必须从提供的图中产生而来，不能自己想象。**

> 另有一条判尺层面的缝，顺手记下但不作为缺陷：仓库判尺对 `labelDimmed` 要求 4.5（正文口径），对品牌色只要求 3.0（UI 口径）。这意味着**调色者只要把品牌色提亮到接近正文亮度，就能轻松拿到 labelDimmed 的余量**——但那样 CTA 就不是 CTA 了。这套稿选择相反的路（压暗浮层、换真实像素），把余量从明度里挣出来，而不是从色相里借。

## 4. 仍然开放、我不替你拍板的四个问题

**Q1 · 这套稿的温度是素材的温度，不是 DC 的温度。**
三张参考图里两张是浅调（徽章圆盘、百科封面），一张是深调群像海报。这套稿读起来是「夜里的 DC」——仓库 notes 原写的是「DC 经典蓝红金」。要后者，得再给一张白天的 DC 参考图。

**Q2 · 主色取徽章的哪一档？**
`#0373B3`（徽章圆盘本体，mass 54,861，反白 4.65:1，UI@面板 3.18:1）与邻档 `#0272B2` / `#025C9A` 的亮度只差 0.5%，但后两档 UI 3:1 会掉到线下。我取的是「圆盘本体那一档」——**这是一个选择，不是唯一解**。

**Q3 · 焦点环是全主题最亮的一档。**
`borderActive #D6F0FF`（Y 0.838）对浮层 10.51、对填充 4.33，余量很好，但它在界面里会「跳」。若想更沉，可用 `#B8D8ED`（对填充 3.55，落进 3:1 但余量薄）。**取舍是审美，不是合规。**

**Q4 · 同一支饱和青要养三个岗。**
`primary #0373B3` / `syntaxFunction #008AC9` / `markdownLink #0392CE` —— function 与 link 之间 ΔE 只有 3.97。原因是**徽章上只有一条饱和青**（#008AC9 / #0392CE / #038FCC 彼此 ΔE 1.45–4.0），而 function 需要 Y ≥ 0.1822、link 需要 Y ≥ 0.2406，窗口里只有一个解。这是**材料上限，不是设计失误**——要拉开，得换素材。

## 5. 我做不到的事（诚实边界）

- **出处拼版是机器判的**：每格是「该 hex 的最近邻最密区」，机器只保证色在图里；「这块看起来像披风还是像装甲」是我逐格目视后写回台账的判断，机器替不了我担保。台账里 `#BDA3B0` 写「封面暗肤玫瑰灰」就属于我看了觉得更像皮肤暗部而非玫瑰。
- **tonal mass 判据是我自己定的**（≥300 材质 / 60–300 渐变 / <60 薄），仓库判尺里没有这一条，它只服务于「宪法」那一条。
- **预览稿是按引擎 token map 手搭的静态稿**，不是真机截图；宿主硬编码的色（tooltip 文字写死白）这套主题改不了。
- **判尺只强制 5 个核心语法的 ΔE76 ≥ 10**，其余 20 个角色的可辨性是我的责任；本稿按 ΔE < 12 自查并把全部近邻列在 §2 末尾。
- **v1 的 37 位也全是真实像素**——被推翻的不是「取色不真」，而是取色之后**在界面里能不能用**（引擎改写、焦点环不可见、层级倒置、描边消失）。这一条记在案，免得把 v1 说成「编色」。
