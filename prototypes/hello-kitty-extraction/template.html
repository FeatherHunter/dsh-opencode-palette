37 个颜色 · 全部有出处

核心只有一句话：让角色本人当配色方案。白脸是纸，粉墙是场，蝴蝶结红是唯一的心跳；蓝背带裤与绿苹果叶只在语义位上露面。四个取舍：

  • 输入框与代码块都取浅色面：shiki 的普通 token 走 --shiki-foreground（= 文字色），深底或重粉底会把无高亮代码压到 3:1 以下。
  • 侧栏用玫瑰粉而不是更浅的粉：侧栏是「海报的墙」，需要和白色内容区拉开 1.9:1 才不至于糊成一片。
  • 主色取蝴蝶结的最深处 #C8152D 而不是最亮的 #E9464D：后者在纸白上只有 3.92:1，撑不起按钮上的白字。
  • 原图里唯一够深的绿只有 #14AE67（2.92:1），所以 success 与字符串压深到 #1B6A42——公式和结果都写在色源台账里。
她的脸是白的，墙是粉的，蝴蝶结是红的——所以界面也该是这样：底是纸，边是墙，只有一处是结。

设计理念

为什么是这 37 个值
01 · 角色即方案
让 IP 自己提供语义

不另造一套「主题色」，而是把角色身上的东西直接翻译成界面角色：白脸→纸面、粉墙→侧栏、蝴蝶结→主色、背带裤→链接、苹果叶→成功、鼻子→警告、小熊棕→行内代码。每个色都能指着图说出处。

02 · 一个心跳
饱和色只给一件事

全库只让 #C8152D 一个高饱和色反复出现，且只出现在主按钮、焦点环、标题与关键字上。侧栏的粉、面板的纱都压在 1.9:1 以内，让界面安静下来，红结才是唯一在跳的地方。

03 · 亮度分层
用台阶而不是边框

纸白 → 淡粉纱 → 浮层粉，三级表面靠明度递进（1.19:1 / 1.44:1）彼此分开。细线只给 1.71:1，够看但不抢戏，结构交给明度而不是线条。

04 · 语义不合并
37 个槽位，32 种色

仓库判尺把「两个角色取同一 hex」记为角色碰撞，理由是语义被抹平。所以这里除仓库已记档的 primary = borderActive（红即品牌即焦点）外，其余角色一律各用各的色：标题、关键字、删除、错误是四个不同深度的红。

05 · 可溯源
每个值都能验

20 个颜色是参考图的精确像素值，可直接在色库里检索到；17 个派生颜色由两枚精确像素按公开公式混合得到（见台账公式列），没有一个是凭感觉写的十六进制。

06 · 过判尺
不只好看，还要合规

跑的是仓库自己的 npm run audit:themes：硬性 4.5:1 与 UI 3:1 违例 0 / 0，语法核心五色 ΔE 全 ≥ 10，注释与操作符都退到核心之下，背景家族无色相孤岛。
