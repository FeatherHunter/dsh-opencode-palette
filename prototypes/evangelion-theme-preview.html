01 / 场

底色是海报，不是画布

深色底取 2.jpg 的海报黑 #151419，面板取 3.jpg 的夜蓝 #111B3E——界面像剧照里的夜空，而不是一块中性灰板。浅色那套则是 3.jpg 的云层。

02 / 骨

骨架靠亮度，不靠边框

八个表面槽是一条亮度梯子（黑 → 暗紫 → 夜蓝 → 浮层），边框只留 #382A5F 一档，避免线框噪声。深色侧栏比页面底略亮，浅色侧栏比页面底略暗——两种模式各按自己的直觉走。

03 / 跳

稀有色才配当主角

绿色只占三张图 2.5% 的面积，红色占 14.1%（口径 B，见 census.py）——所以同步绿只当成功态，红色留给错误与删除行，海报标题的橙独占警告。

04 / 义

一槽一色，不撞车

深浅两套各 37/37 个颜色都是互不相同的色值：同一色相家族用不同明度台阶区分语义（新增行 / 成功 / 字符串各占一阶），避免"角色语义被抹平"。

惣evangelion.json

37 个颜色 · 每个色值都能溯源

整套配色只有两个动作：直采 与 定比混色。对抗式审查推翻了第一版的「直采」定义——离原图最近的那个像素会锁死在 JPEG 振铃与文字描边上（第一版 44 个锚点里 17 个整图只有 1 个同色像素，颜色名还与实际像素对不上）。现在的直采 = 平涂区域代表色：该处 3×3 邻域方差为 0、同色像素成片存在。混色写明配方与比例，任何人都能复算。核心取舍：

  • 错误色不取图里的纯红 #DC4C2A：它在浮层底上只有 3.37 : 1；改取「装甲红受光面 #D8402B × 云白 35%」，#E3796A 落到 6.29 : 1，八个表面上全部过线。
  • 判尺之外另做真机复核：把配色灌进仓库真实编辑器原型截图，量出三处审计器看不见的失败——行内码芯片 6.16 : 1、浅色次按钮药丸 6.95 : 1、浅色信息按钮白字 14.39 : 1。三条已修，并已写进判尺常驻（见下方审计表）。
  • 深浅两套不是「反过来」：浅色底来自 3.jpg 的云层 #EFF2F7，文字用 2.jpg 的夜蓝 #181824，所以白天那套是天空，不是同一批颜色反相。
  • 同一色相家族用不同明度台阶区分语义：新增行 #AFC755、成功态 #DBFD68、字符串 #89B872 三阶分开，37 个槽两套各 37 个不同色值，零角色碰撞。
  • 六个品牌色都会被引擎当填充色用（按钮底 / 徽标底），所以每个品牌色都必须落在 BT.601 luma 0.6 的同一侧，否则引擎的 pickText 会挑到读不清的那一支——浅色信息色就是这么翻车的。
黑色是海报的夜，绿是同步的呼吸，红是明日香——三种情绪各占一个色相家族，互不串味。

37 Color Slots

左起两枚色块 = 深色 / 浅色；右二列为各自的取色配方

颜色与 DSH 的 --dsw-alias-* 变量一一对应（取自 src/engine/map-dsh.ts）。 直采 = 参考图里一块平涂区域的代表色（同色像素成片、3×3 邻域方差 0）；定比混色 = 两个采样色的固定比例，配方可复算。

取色溯源

每块色值都标出了它来自哪张图的哪个位置

下面每一张缩略图都是从参考图里裁下来的原像素区域，颜色即该区域的实际取样值。 锚点全部来自三张参考图，没有任何外部色卡；每张缩略图下方标出该颜色在原图里的同色像素数与邻域方差（方差 0 = 真平涂，不是描边也不是振铃）。其中 2 个锚点（林绿 / 冷纸白）在三张图里找不到成片平涂面，保留声明值并在卡片上如实标注。

对比度审计

WCAG 2.1 相对亮度比 · 正文/语义色 ≥ 4.5:1，非文本组件 ≥ 3:1

口径与仓库 docs/theme-audit/criteria.md 一致：label-dimmed 按 withAlpha(textMuted, 0.8) 在 gamma 编码的 sRGB 空间合成后再比。

表分三级口径：判尺硬性（仓库判尺 + 第四轮机器约束：混色闸 / 表面分离 / 色觉分离）必须全过；诊断级是判尺之外的自加项——本件 6 条未达 4.5:1，都是「markdown 角色 × 代码头带 / 输入面」这类不同屏的组合（输入框里不出现 markdown，代码标题条上也不出现行内代码），已逐条列出而非藏起来；记账是只统计不判罚的诊断行（去色盲模拟、退后带）。
