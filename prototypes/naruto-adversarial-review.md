### 1.1 盲测的正面结论（保留为设计依据）

> 盲测（16 个身份、名字遮住）：1 猜 = harry-potter(dark) / disney(light)；dragon-ball 在 95 个里排第 11。

这条是 v10 的验收线：**火影必须比龙珠更容易被认出**。龙珠的主音是「纯正高饱和橙 + 蓝」，

悟空是 C\* 74.2、马里奥 79.7、乐高 85.0），
让 `secondary` 走**低彩深藏青**（C\* 21.5 / 21.9）而不是悟空的鲜蓝，

拉开距离的量是**彩度**不是色相 —— 见 §六.2 的诚实账。

## 三、决策链：v3 → v10

```
v1  自造暖米纸色（作废，用户判「不能自己想象」）
 └ v2/v3  照抄像素（37 槽逐支反查原图命中，判尺 0 违例）
     └ 问题：响度颠倒、8 表面 85% 同灰、dark 与龙珠撞车、light 像迪士尼
         └ v4  评审派生（锚点众数 + 显式 L*/C*）—— 浅色语义彩度跨度 5.4×→2.0×，但 dark 近重复反多
             └ v5  求解器 v1（逆变换漏 gamut 映射）—— primary 变粉红，整套塌掉
                 └ v6  逆变换修好但立方写错 —— 全近白
                     └ v7/v8/v9  三次修正求解器（立方逆变换 + 二分 gamut 映射 + MAXC 预计算 + 记忆化 labOf + 岗位串戏否决）
                         └ v10 定版：两册 0 违例 / 0 告警 / ΔE2000 最小 1.59（亮）· 2.01（暗）
```

**v10 的派生规则（一句话可复现）**：

> 锚点（取自参考图的真实像素区域，**色相 H 保持不变**，避免跑色）
> → 设 L\*（明暗） → 设 C\*（彩度） → LCh → sRGB（立方逆变换 + 二分 gamut 映射）→ 色位

**为什么是「锚点 + 规则」而不是「直采」**：直采只能覆盖 9 条真正的平涂色（区域众数 200–12000 px），
剩下 28 个色位必须靠明暗与彩度展开；展开时唯一能保证「还是火影」的量就是色相。
用 `#96593D`（8 px 的抗锯齿缝）当 primary 属于把 JPEG 伪影提升成设计色。

## 四之二、收官阶段新查出的两件事（都不是第一轮报告里的）

### 4.2.1 暗册冒出一条**色相孤岛**告警 —— 气泡的樱红

第一轮自查只看了「自己写的 check.mjs」，没跑仓库判尺的 `hueIslands`；把 v10 写进仓库后判尺报出：

> `naruto-night` 的 bubbleBg `#43292B`（H 15.9）与该册基色 H 279 相差 97°，超出「8 个背景槽里彩度 ≥8 的必须落在基色 ±60°」。

**修法**：气泡改成同一藏青家族里偏紫的 `#3A3746`（L\*23.9 C\*10.1 H299.4）—— 告警清零。
**代价**：暗册失去了唯一一抹樱色，改由 `error #D76979` 与 `markdownEmph #EDAAAF` 承担。
**教训**：自写的复刻判尺只能证明「我写的那套规则过了」，证明不了「仓库那套规则过了」；必须以仓库判尺实跑为准。

### 4.2.2 判尺全绿 ≠ 出货即最终值：运行时会改写 diff 色

用仓库引擎 `ensureDiffContrast` 直接跑作者值，发现**暗册会被改写 2 槽**：

```
diffRemovedLineNumberBg: #523D3E -> #3C2B35      （把 diffRemoved 的对比从 4.36 拉到 4.5+）
diffRemovedBg:           #352023 -> #3C2B35      （顺带把两个 diff 底压成同一个值）
```

判尺查的是**作者值**，运行时兜底是**另一套算法**（`resolve.ts:221`）。作者值满足硬性 4.5 但没满足引擎的合成口径，
运行时就会悄悄改色 —— 而且改完两个 diff 底撞成同值。
**修法**：把 `diffRemovedLineNumberBg` 提前压深到 `#4D393A`（`diffRemoved` 对它 4.66:1），引擎 0 改写。
**这是本次审查里最实操的一条**：任何 diff 六槽，都要用 `ensureDiffContrast` 跑一遍确认 no-op。

## 五、响度实测（渲染像素，不是纸面推算）

用 playwright 渲染本页 mockup 后逐像素统计（`measure_loudness.py`，响度指数 = 面积占比% × C\* / 10）：

| 角色 | 亮册 | 暗册 |
|---|---|---|
| bubbleBg | 10.71% ｜ C\*13.3 ｜ **14.2** | 11.81% ｜ C\*10.1 ｜ **11.9** |
| backgroundElement | 8.46% ｜ C\*9.7 ｜ 8.2 | 8.85% ｜ C\*12.1 ｜ 10.7 |
| primary | 1.05% ｜ C\*45.8 ｜ 4.8 | 1.14% ｜ C\*48.0 ｜ 5.5 |
| codeHeaderBg | 2.30% ｜ C\*16.5 ｜ 3.8 | 2.47% ｜ C\*19.8 ｜ 4.9 |

**结论**：这两册的响度不是由品牌色拿的，而是由**大面积低彩表面**拿的。
这是 v2 视觉审查指出的「响度颠倒 6.9:1」的**结构性解**——不是把 primary 调得更艳（那会牺牲对比度余量），
而是让大面积表面本身承担气质（晒过的和纸 / 夜之暗藏青），品牌色退到「点缀级响度」。
代价要说清楚：**这套盘子的第一眼不会跳出来橙色**，它需要看第二眼。这是「参考图里就没有大面积橙色」这个素材事实的直接后果。

## 六、遗留风险（明说，不藏）

1. **亮册的 8 个表面槽彩度只有 2.1–16.5**，`#F7F5EF` / `#F0EDE8` / `#E0D9C7` 与其它浅色 IP 预置的最小 ΔE76 只有 1.7 量级 —— **主题独特性的上限被「浅色纸面」这个定位卡死**。要跳出来只能改定位（例如把亮册做成「漫画网点纸」而不是「米白纸」），那会离开参考图的字面像素。
2. **暗册的 `#0A0E18` 与 mario-night 的背景 ΔE76 = 2.65**（star-wars 3.56、marvel 4.5、evangelion 5.47、cyberpunk-2077 6.56）。近黑底撞不过去，也不必撞：差异在 `#EF9568`（暖橙主音）与 `#F0DC94`（暖金标题）这两支上。
3. **`#1F1E1C`（乌鸦墨）只取到 37 px 连通块**，`#0E4937`（乌鸦暗部松绿）只有 17 px —— 这两支是全套里最脆的锚点，任何重压缩都可能让它们消失。
4. **亮册按钮字 `#F4F4F5` 不是图像像素**（引擎 `contrastText` 对亮色 primary 固定给 `#F4F4F5`）。这是引擎行为，不进锚点表。
5. **亮册 `primary` 的 C\* 45.8 低于 v3 派生版的期望** —— 换来的是 `primary@backgroundPanel` 4.73:1 的宽余量与「不是悟空橙」的可分性。**这是取舍，不是遗漏。**
6. **暗册丢了唯一一抹樱色**：气泡原为樱红 `#43292B`，因色相孤岛告警改成藏青家族紫 `#3A3746`（§4.2.1）。这是判尺优先于素材意愿的一次真实让步。

### 6.2 岗位串戏的诚实账

用审查方给的粗口径（HSL 色相 ≤15° 且 |Δ WCAG 亮度| ≤0.05）逐槽比对仓内 23 个 IP 预置：

| 半册 | 最近邻 | 6 品牌槽平均 ΔE76 | 粗口径近碰撞 |
|---|---|---|---|
| 亮册 | dragon-ball | 22.5 | dragon-ball 1/6、hello-kitty 4/6、mario 4/6、sailor-moon 2/6 |
| 暗册 | harry-potter | 27.3 | hello-kitty 1/6、star-wars 1/6、transformers 1/6、cyberpunk 1/6、evangelion 1/6 |

**这个口径在本主题上会误报**：它只看色相与 WCAG 亮度，对高彩度红橙区的 HSL 色相极不稳定。逐槽复算感知距离：

| 对 | 感知距离 | 靠什么拉开 |
|---|---|---|
| 亮册 primary `#A0542D` vs 龙珠 primary `#BD3C03` | ΔE2000 **8.1** / ΔE76 28.7 | 彩度 C\*45.8 vs 74.2（同明度 L\*44、同色相 H52 vs 47.8） |
| 暗册 primary `#EF9568` vs 龙珠 primary `#BD3C03` | ΔE2000 **24.8** / ΔE76 37.0 | 明度 L\*70 vs 44 + 彩度 48 vs 74 |
| 亮册 primary vs 马里奥 `#C7280E` | ΔE2000 11.3 | 彩度 45.8 vs 79.7 |
| 亮册 primary vs 乐高 `#d01012` | ΔE2000 13.6 | 彩度 + 色相 |

**结论**：两册的 `primary` 与所有「合成高彩度橙红」的 IP 预置都处在同一色相带内，
拉开距离的是**彩度与明度**，不是色相。素材侧的原因是硬性的：参考图的战衣橘是**照片固有色 C\*48**，
不是设计师挑的高彩度橘。要彻底脱开这一带，只能放弃「鸣人战衣橘」这个锚点 —— 那就等于放弃「火影」这个身份。
**这是取舍，不是缺陷。**
