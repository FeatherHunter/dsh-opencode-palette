## 3. 审完仍然成立的部分（验真清单）

- **色相占比是素材给的，不是设计的**：三张图里 蓝紫 35.1% / 中性 37.6% / 红 14.1% / 琥珀 8.0% / 绿 **2.5%**。所以「绿色只配当主角」是画面的事实，不是我的偏好。
- **diff 不被引擎改写**：`ensureDiffContrast` 在两个底色均已达标时原样保留（`resolve.ts`），本稿两半都不触发重算。
- **token 落点核过**（`map-dsh.ts`）：`diffAddedBg`→`file-diff-added-bg`、`diffAddedLineNumberBg`→`file-diff-added-gutter`、`codeHeaderBg`→`--dsl-code-block-background`、`backgroundElement`→tooltip/toast/selector、`secondary`→`state-idle-primary`（**不是填充色**）、`borderActive`→border-l2/l3/l4 + ghost-active-border + scrollbar-hover。
- **语法退后**：深色 comment 5.60 / operator 5.08 ≤ 核心最低 6.30；浅色 6.91 / 5.59 ≤ 7.45 ✔。
- **深浅两套各自成立，不是反相**：浅色半的底来自 3.jpg 云层 `#EFF2F7`，文字来自 2.jpg 夜蓝 `#111B3E`。
- **每个品牌色都被引擎当填充色用**（按钮底/徽标底），所以六色必须在 luma 0.6 的同一侧——这是 F4 的根因，已写进判尺。

## 4. 仍然开放、我不替你拍板的五个问题

**Q1 · 主题的温度 = 参考图的温度。**
三张图是海报/剧照，不是夜景演出。绿色只占 2.5%，所以深色半读作「**夜战**」而不是「EVA 紫」；而荧幕上的 EVA 标志其实是紫 + 荧光绿的组合。要更绿，就得接受绿在图里没有平涂面可取。

**Q2 · 主色给紫还是给同步绿？**
现稿主色 = 机体紫 `#BB96F5`，荧光绿 `#DBFD68` 只当成功态。仓库里已发布的旧 `evangelion` 预置把主色给了绿（`#84ff00`）、紫给副色。**两者都成立**：紫更接近装甲，绿更接近同步器闪烁。取舍是审美不是合规。

**Q3 · 红色 diff 行的可见度有客观上限。**
图里最纯的红 `#DC4C2A`（BT.601 L ≈ .2026）在任何染色行底上都到不了 4.5:1。旧预置的 `#ff7a93` 好看，是因为它是**编出来的**。在「不许造色」前提下，删除行只能保证 4.5:1 可读 + 行号槽 ΔE 分离，**做不到「一眼就跳出来」**。

**Q4 · 两个锚点是声明值，不是取样值。**
`forest #2B4429`（林绿）与 `paperCool #F8FAF9`（冷纸白）在三张图里找不到成片平涂面——林绿几乎全被 JPEG 振铃打碎，冷纸白只有零星像素。要么接受标注，要么补第四张参考图。

**Q5 · 焦点环 33% alpha 到不了 3:1。**
真机实测焦点环 1.73（深）/1.58（浅），但这是 `borderActive` 叠 33% alpha 的**原型渲染属性**：白@33% 压暗底的上限也只有 2.66:1，**任何色板都过不去**。旧 EVA 预置 2.55、库洛米 1.51 同属一类。要不要动原型（把焦点环改成实色或提高 alpha）是另一个决定，不属于色板。

## 5. 我做不到的事（诚实边界）

- 预览页是**静态稿 + 真机原型截图**两条腿。真机复核用的是仓库真实的 widget 渲染（`prototypes/custom-editor-83.prototype.html`），**不是宿主真身**。
- 审计器只强制核心 5 个语法的 ΔE76 ≥ 10，**其余 20 个角色的可辨性是我的责任**；本稿按「ΔE < 5 即缺陷」自查并已清零。
- 焦点环 33% alpha 不可修（见 Q5）。
- 颜色**只来自这三张参考图**，没有引入第四张图、没有任何外部色卡；两处例外（forest / paperCool）已在锚点表如实标注。
- 仓库当前有并发会话正在改其他 IP 主题（genshin-night 等），落库前需与其收口结果合并。
