## 3. 审完仍然成立的部分（验真清单）

- **色相占比是素材给的，不是设计的**：三张图里 蓝紫 35.1% / 中性 37.6% / 红 14.1% / 琥珀 8.0% / 绿 **2.5%**。所以「绿色只配当主角」是画面的事实，不是我的偏好。
- **diff 不被引擎改写**：`ensureDiffContrast` 在两个底色均已达标时原样保留（`resolve.ts`），本稿两半都不触发重算。
- **token 落点核过**（`map-dsh.ts`）：`diffAddedBg`→`file-diff-added-bg`、`diffAddedLineNumberBg`→`file-diff-added-gutter`、`codeHeaderBg`→`--dsl-code-block-background`、`backgroundElement`→tooltip/toast/selector、`secondary`→`state-idle-primary`（**不是填充色**）、`borderActive`→border-l2/l3/l4 + ghost-active-border + scrollbar-hover。
- **语法退后**：深色 comment 4.78 / operator 5.04 ≤ 核心最低 7.16；浅色 comment 5.33 / operator 5.60 ≤ 核心最低 5.89 ✔。
- **深浅两套各自成立，不是反相**：浅色半的底来自 3.jpg 云层 `#EFF2F7`，文字来自 2.jpg 夜蓝 `#111B3E`。
- **只有 primary 与 info 会被引擎当填充色用**（真机原型 `custom-editor-83.prototype.html:865/867`），其余四个品牌色只做文字、图标与圆点。所以 luma 0.6 同一侧这条只约束 primary / info —— 这是 F4 的根因、F17 的收窄，已写进判尺（`FILLED_BUTTON_ROLES = ['primary', 'info']`）。
- **第四轮新增的机器约束**（全部写进 `build_palette.py` 的 `evaluate()`，不再靠人眼）：
  - **混色闸**：74 个出货色每一个都要落在三张原图全部像素的 ΔE76 ≤ 2.0 内——「不许造色」从此是可执行的门，不是承诺。当前最远的一条 ΔE76 = 1.38。
  - **表面分离**：8 个结构面两两 ΔE76 ≥ 2.0（真撞色才拦），并记录每半的明度跨度。两半各 28 对全部过线，最紧的一对是深色半 `background × inputBg` 4.73、浅色半 `background × backgroundElement` 4.23。
  - **色觉分离**：按**同屏共现分组**（PROSE / CODE / STATUS / DIFF）而不是全局两两，并分三级 —— `pure`（语法色之间、`diffAdded × diffRemoved`、STATUS 内除 `primary × secondary`）要求常态 ΔE76 ≥ 8 且 protan/deutan/tritan 模拟 ΔE ≥ 8；`decor`（还有别的通道承载的配对）要求模拟 ΔE ≥ 5；`hier`（正文 × 次级）要求 ΔL\* ≥ 6；`recede`（注释 × 运算符）**只记账、不判可分**（见 F18）。**去色盲（achroma）只作诊断行、不设硬阈值** —— 要求每一对在完全去色下 ΔE ≥ 8，等价于要求每个角色都有 ΔL\* ≥ 8 的明度阶梯，37 色的 UI 做不到。
  - **余量账本**：每条硬性检查记录 `ratio − threshold`，配方在判尺允许的空间里取余量最大的一支。当前余量 < 0.6 的只有深色半两条（`syntaxComment` +0.28、`syntaxOperator` +0.54），浅色半最薄 +0.83。
- **状态语义不靠色相单独承载**：error / warning / success 三色按**明度台阶**排开（深色半 L\* 62.5 / 54.2 / 94.4，浅色半 18.0 / 39.1 / 30.0），所以在红色盲与去色盲下仍然分得开。

## 4. 仍然开放、我不替你拍板的十个问题

**Q1 · 主题的温度 = 参考图的温度。**
三张图是海报/剧照，不是夜景演出。绿色只占 2.5%，所以深色半读作「**夜战**」而不是「EVA 紫」；而荧幕上的 EVA 标志其实是紫 + 荧光绿的组合。要更绿，就得接受绿在图里没有平涂面可取。

**Q2 · 主色给紫还是给同步绿？**
现稿主色 = 机体紫 `#BB96F5`，荧光绿 `#DBFD68` 只当成功态。仓库里已发布的旧 `evangelion` 预置把主色给了绿（`#84ff00`）、紫给副色。**两者都成立**：紫更接近装甲，绿更接近同步器闪烁。取舍是审美不是合规。

**Q3 · 红色 diff 行的可见度有客观上限。**
图里最纯的红 `#DC4C2A`（BT.601 L ≈ .2026）在任何染色行底上都到不了 4.5:1。旧预置的 `#ff7a93` 好看，是因为它是**编出来的**。在「不许造色」前提下，删除行只能保证 4.5:1 可读 + 行号槽 ΔE 分离，**做不到「一眼就跳出来」**。

**Q4 · 两个锚点是声明值，不是取样值。**
`forest #2B4429`（林绿）与 `paperCool #F8FAF9`（冷纸白）在三张图里找不到成片平涂面——林绿几乎全被 JPEG 振铃打碎，冷纸白只有零星像素。这两个还要分开看：冷纸白的目标色**确实是原图像素**（只是没有成片平涂面），林绿的目标色在三张图里**连一个像素都不是**（`targetIsPixel = false`）。要么接受标注，要么补第四张参考图。

**Q5 · 焦点环 33% alpha 到不了 3:1。**
真机实测焦点环 1.73（深）/1.58（浅），但这是 `borderActive` 叠 33% alpha 的**原型渲染属性**：白@33% 压暗底的上限也只有 2.66:1，**任何配色都过不去**。旧 EVA 预置 2.55、库洛米 1.51 同属一类。要不要动原型（把焦点环改成实色或提高 alpha）是另一个决定，不属于配色。

**Q6 · 浅色半的状态色是「墨色」而不是「亮色块」。**
白底上 4.5:1 的硬约束把状态色压到 L\* ≤ 45，于是浅色半的 error / warning / success 只能是深红、深铜、深林绿（色度低、像印刷墨）。这是空间约束的结果，不是审美偏好：想要浅色半也有鲜艳的绿，必须放弃「状态文字在白底上 4.5:1」。**要不要为了鲜艳牺牲浅色半状态文字的可读性，是你的决定。**

**Q7 · 混色闸的容差 2.0 是我划的线，不是物理定律。**
ΔE76 ≤ 2.0 意味着「出货色必须是图里真实存在（或几乎存在）的颜色」。放宽到 3 就允许更多手工调色；收紧到 1 就只剩原图原样。**这条线是「不许造色」这句话的可执行版本，线画在哪是你的决定。**

**Q8 · 「同屏共现分组」是我的建模，不是仓库判尺的原文。**
`docs/theme-audit/criteria.md` 要求全局 38 对正文 + 15 对 UI；我额外按「会同屏出现」把角色分进 PROSE / CODE / STATUS / DIFF 四组，只在组内要求色觉分离。理由是不同屏的角色（例如正文里的次级文字与代码里的关键字）本来就不需要互相区分。**如果你的产品会出现「同一屏同时出现这些角色」的情况，这个分组就要重画**——分组一改，判尺跟着改。

**Q9 · 语义色相带目前只是告警，要不要升级成硬失败？**
第四轮给 20 个角色定了 `HUE_BAND` + `CHROMA_MIN`（error 得是红、warning 得是琥珀、link 得是蓝……），越界只记**设计告警**，不算硬失败。理由是判尺只管「可辨性」，色族是「设计意图」。但「设计意图」这种东西一旦只靠自觉，半年后就没人记得当初为什么把 error 调成那个橙。**升级成硬失败还是继续只告警，是你的决定**——升级的话，配方空间会小很多。

**Q10 · 浅色半的「退后」余量只有 0.83，值不值得为它牺牲别的？**
浅色半注释 5.33 / 运算符 5.60 已经贴着核心最低 5.89，余量只剩 0.83（深色半更薄，只有 0.28）。我试过整体加深核心语法色去撑，结果核心角色挤成同一片深色、硬违例立刻冒出来（已回滚，见 F21）。**要么接受这个薄余量，要么改核心语法色的明度结构**——后者会动到整套浅色半的语法配色。

## 5. 我做不到的事（诚实边界）

- 预览页是**静态稿 + 真机原型截图**两条腿。真机复核用的是仓库真实的 widget 渲染（`prototypes/custom-editor-83.prototype.html`），**不是宿主真身**。
- 审计器只强制核心 5 个语法的 ΔE76 ≥ 10，**其余 20 个角色的可辨性是我的责任**；本稿按分级判据自查（`pure` 级模拟 ΔE ≥ 8、`decor` 级 ≥ 5、`hier` 级 ΔL\* ≥ 6，注释 × 运算符只记账、去色盲只诊断），但台账**不是全绿**：浅色半有 4 条扩展矩阵诊断（markdown 角色压在浅色代码头带上）低于 4.5:1，深色半有 2 条状态色 `contrastText` 诊断没过（3.51 / 2.65）。这两类都是**诊断级**、不影响真机渲染，但它们确实存在，不该被写成「全过」。
- 焦点环 33% alpha 不可修（见 Q5）。
- 颜色**只来自这三张参考图**，没有引入第四张图、没有任何外部色卡；两处例外（forest / paperCool）已在锚点表如实标注。另一个容易误读的地方：44 个锚点里 39 个的**目标色不是原图像素**，所以 `target` 是目标不是证据（见 F23）。
- 仓库当前有并发会话正在改其他 IP 主题（genshin-night 等），落库前需与其收口结果合并。
